--------------------------------------------------------------------------------
1. DATASET
--------------------------------------------------------------------------------

Source      : putEMG (Poznan University of Technology, Kaczmarek et al. 2019)
Subjects    : 44 able-bodied subjects processed (03–07, 08–20, 22–27, 29–31,
              33–36, 38–39, 42–43, 45–51, 53–54)
              IDs 21, 28, 32, 37, 40, 41, 44, 52 not present in dataset
Channels    : 24 sEMG electrodes (ring around the forearm)
Sampling    : 5120 Hz
Gestures    : 7 classes — G1, G2, G3, G6, G7, G8, G9
Protocol    : ~40 reps/gesture/subject  (2 sessions × 5 series × ~4 reps)
              Each rep: ~280 samples per subject after preprocessing

Raw data    : one CSV per session per subject
              24 EMG channels + 1 trajectory label (0=rest, 1–9=gesture, -1=ignore)

--------------------------------------------------------------------------------
2. PIPELINE
--------------------------------------------------------------------------------

STAGE 1 — Signal Preprocessing
  Code : data_preprocessing/preprocessing.py
         data_preprocessing/driver.ipynb
  Steps: bandpass 20–500 Hz (zero-phase Butterworth, order 4, before resampling)
         → resample to 1500 samples
         → per-channel z-score normalization
  Output: /Volumes/KRIS/data/UG_per_subject/emg_gestures_SS_U.mat  (44 files)
  Shape: combinedCell (N_reps, 7), each cell (1500, 24) float64

STAGE 2A — Feature Extraction (for feature-based approach)
  Code : public/feature_extraction.py  (primary — uses libemg)
         data_preprocessing/feature_extraction.py  (legacy — 8 manual features)
  Window: size=250 samples (~49 ms), shift=50 samples (~10 ms) → 26 windows/rep
  Features (libemg): 50 feature groups × 24 channels = 3192-dim vector per window
    Full list: MAV, ZC, SSC, WL, LS, MFL, MSR, WAMP, RMS, IAV, DASDV, VAR,
               M0, M2, M4, SPARSI, IRF, WLF, AR, CC, LD, MAVFD, MAVSLP, MDF,
               MNF, MNP, MPK, SKEW, KURT, RMSPHASOR, PAP, WLPHASOR, MZP, TM,
               SM, SAMPEN, FUZZYEN, DFTR, ISD, COR, MDIFF, MLK, ACT, MOB,
               COMP, WENG, WV, WWL, WENT, MEAN
    Note: some features (AR, CC, DFTR) are multi-valued → 133 scalars/channel total
  Output format: (26, 3192) per rep — temporal sequence
  Output files : features_subject_SS_sequence.npz  (skip logic: existing files skipped)

STAGE 2B — Deep Learning Data Loading
  Code : public/emg_loader.py
  Loads preprocessed .mat files at runtime; reshapes to (N, 1, 24, 1500)
  LOSO splits via make_loso_train_val_test()
  Split: Test=1 held-out subject | Train=90% of 43-subject pool | Val=10% of pool

3. APPROACHES
--------------------------------------------------------------------------------

  APPROACH A — Deep Learning (raw signal, end-to-end)
    Input shape : (1, 24, 1500) per rep

    Notebook    : generalizable/baseline_models/deep_learning_approach/model.ipynb

    Status      : COMPLETE — 44/44 folds for all 3 models

  APPROACH B — Feature-Based (sequence model on hand-crafted features)
    Input shape : (26, 3192) per rep — temporal sequence of 3192-dim feature vectors
    Models      : LSTM, GRU, Transformer (to be determined)

    Status      : Feature extraction infrastructure complete; training not yet run

  NOTE: splits must be at the rep level (not window level) to avoid data leakage.

--------------------------------------------------------------------------------
4. MODEL ARCHITECTURES — Deep Learning Approach
--------------------------------------------------------------------------------

  All models: NUM_CLASSES=7, NUM_CHANNELS=24, INPUT_SAMPLES=1500
  Code: public/deep_learning_models.py

  EEGNet         — depthwise + separable convolutions; standard BCI architecture
  ShallowConvNet — temporal conv → band-power pooling (x² → avgpool → log)
  DeepConvNet    — deeper block-based CNN                [disabled — needs more data]
  CNN_LSTM       — spatial CNN + temporal LSTM           [disabled — poor performance]
  EMG_TCN        — dilated temporal convolutions + residual connections

  Training config (model.ipynb):
    Optimizer    : Adam (lr=1e-3)
    LR scheduler : ReduceLROnPlateau (factor=0.5, patience=5, min_lr=1e-6)
    Early stop   : patience=5, min_delta=0.002
    Max epochs   : 20
    Dropout      : 0.1
    Batch size   : 16
    Best-state   : checkpoint restored from best val epoch before test eval

6. BUGS FOUND AND FIXED
--------------------------------------------------------------------------------

  [FIXED — 2026-04-09]  dtype bug in evaluateFinal()
    actual = torch.tensor([]) and predicted = torch.tensor([]) created float32
    empty tensors. torch.cat with int64 label tensors silently promoted to
    float32, corrupting confusion matrix class labels. Fixed: dtype=torch.int64.

  [FIXED — 2026-04-09]  dead loop in loso_folds()
    A partially-converted generator had a dead for loop wrapping a return.
    Fixed: removed the loop; loso_folds() is now a clean single-fold function.

--------------------------------------------------------------------------------
8. WEAKNESSES & GAPS
--------------------------------------------------------------------------------

  1. HIGH LOSO VARIANCE — cross-subject generalization is inconsistent
     All models show ~12 pp std. Some subjects are near-perfectly classified
     (>98%) while others are near-chance (<50%). Root cause unknown: could be
     signal quality, individual anatomy, or gesture execution style.
     Subject-adaptive methods are likely required for deployment.

  2. NO FEATURE-BASED RESULTS YET
     Feature-based approach has no accuracy numbers. Cannot compare against
     deep learning or answer whether hand-crafted features compete with
     learned representations.

  3. NO PER-CLASS ACCURACY BREAKDOWN
     All results are overall accuracy. Per-class breakdown would reveal which
     gestures fail to generalize — no retraining needed, only forward passes
     on existing checkpoints.

  4. G9 LIKELY HARD TO CLASSIFY CROSS-SUBJECT
     After per-rep z-score removes amplitude, G9 (little finger pinch) may
     be nearly indistinguishable from similar gestures for waveform models.

  5. CHANNEL CLUSTERING NOT FINALIZED
     The 24→8 channel reduction experiment has code but no results yet.

  6. NO SUBJECT-ADAPTIVE FINE-TUNING
     Given large LOSO variance, fine-tuning on a few calibration reps from
     the test subject is the most practical next step for deployment.
