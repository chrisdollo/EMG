putEMG Prime — Feature Approach: Three Classification Strategies
================================================================

This document describes the three ways extracted EMG features will be organized
and fed to classifiers. All three share the same underlying feature extraction
(8 features × 24 channels = 192 values per window) but differ in how windows
are grouped, what constitutes a "sample", and how inference works.

─── SHARED SETUP ─────────────────────────────────────────────────────────────

Input data (per subject):
  - 40 repetitions × 7 gesture classes = 280 gesture reps per subject
  - Each rep: 1500 samples × 24 channels (preprocessed, resampled from 5120 Hz)

Sliding window:
  - Window size : 250 samples (~49 ms at 5120 Hz)
  - Window shift: 50 samples  (~10 ms stride)
  - Windows per rep: floor((1500 - 250) / 50) + 1 = 26 windows

Feature extraction (per window):
  - 8 features computed per channel: MAV, RMS, WL, ZC, SSC, VAR, MNF, MDF
  - 8 features × 24 channels = 192-dimensional feature vector per window

─── FORMAT 1 — FLAT PER REP ──────────────────────────────────────────────────

Concept:
  All 26 windows from a single gesture rep are concatenated into one flat vector.
  The entire gesture is treated as a single data point.

Shape per sample : (4992,)   [26 windows × 192 features]
Dataset shape    : (280, 4992)   [280 reps, one label per rep]
Labels           : one label per gesture rep (0–6)

How it works:
  For each gesture rep, the 26 window feature vectors (each 192-dim) are
  extracted in order and concatenated end-to-end into a single 4992-dim vector.
  The temporal order of windows is preserved in the concatenation — the first
  192 values correspond to the first window, the last 192 to the final window.
  No temporal structure is explicitly modeled; the classifier sees all windows
  simultaneously as one large flat input.

Suitable models:
  - SVM (LinearSVC, RBF kernel) — strong baseline for tabular/flat data
  - XGBoost / LightGBM / Random Forest — handles high-dimensional input well
  - MLP — fully connected network on the flat vector

Use case:
  Offline classification where the full gesture recording is available before
  predicting. Simplest possible input format. Good starting baseline to
  understand how much information the features carry across the full gesture.
  High-dimensional input (4992) may require regularization or feature selection
  to avoid overfitting with small datasets.

Inference:
  Capture the full gesture signal (1500 samples), apply the sliding window to
  extract all 26 windows, compute features for each, concatenate → one (4992,)
  vector → single model call → single predicted label.
  Latency: must wait for the entire gesture to complete before classifying.

─── FORMAT 2 — FLAT PER WINDOW ───────────────────────────────────────────────

Concept:
  Each of the 26 windows is treated as an independent sample with its own label
  (inherited from its parent gesture rep). This is the current default output
  of feature_extraction.py.

Shape per sample : (192,)   [8 features × 24 channels]
Dataset shape    : (7280, 192)   [280 reps × 26 windows, one label per window]
Labels           : one label per window (same as the rep it came from)

How it works:
  Each 250-sample window is processed independently. The 8 features are
  computed for each of the 24 channels and arranged as a flat 192-dim vector.
  Every window gets the gesture label of the rep it belongs to. The model has
  no knowledge that consecutive windows came from the same rep — it classifies
  each 49ms slice in isolation.

Important note on train/test splitting:
  Windows from the same gesture rep must NOT be split across train and test
  sets. Splitting must be done at the rep level (or subject level) and then
  windows are derived from whichever reps end up in each split. Splitting at
  the window level would cause data leakage.

Suitable models:
  - SVM (LinearSVC, RBF kernel) — primary target for this format
  - XGBoost / LightGBM
  - MLP — lighter network than Format 1, 192-dim input
  - 2D CNN — reshape each window to (24, 8) before passing in, treating
    channels and feature types as spatial dimensions

Use case:
  Both offline and real-time/online classification. In a real-time scenario
  this is the most natural format: as EMG streams in, each new window is
  classified immediately without waiting for a full gesture to complete.
  Majority voting across windows of the same rep improves reliability in
  offline evaluation. This format produces the largest dataset (7280 samples
  per subject) which helps with model generalization.

Inference (offline):
  Slide window over the full gesture (26 windows), classify each independently,
  take the majority-vote label (or soft-vote by averaging class probabilities)
  across all 26 predictions → final label.

Inference (real-time):
  As EMG streams in, extract a new window every 10ms (50 samples), compute
  features → 192-dim vector → single model call → immediate prediction.
  No voting required; each prediction is valid on its own. A smoothing buffer
  (e.g. rolling majority vote over the last N windows) can reduce jitter.

─── FORMAT 3 — SEQUENCE PER REP ──────────────────────────────────────────────

Concept:
  All 26 windows from a gesture rep are kept in temporal order as a sequence.
  Each timestep in the sequence is a 192-dim feature vector. The model sees
  how EMG features evolve across the full duration of the gesture.

Shape per sample : (26, 192)   [26 timesteps × 192 features]
Dataset shape    : (280, 26, 192)   [280 reps, one label per rep]
Labels           : one label per gesture rep (0–6)

How it works:
  Feature extraction is identical to Format 2 — 26 windows, each producing a
  192-dim vector. The difference is that the 26 vectors are stacked into a
  matrix (26, 192) rather than being treated as independent samples. The model
  receives the entire temporal sequence for one gesture rep and produces a
  single classification. This preserves the dynamic structure of the gesture:
  the onset, peak activation, and offset phases are all visible to the model.

  Note on shape ordering: (26, 192) follows the PyTorch convention of
  (seq_len, features) per sample, i.e. (batch, seq_len, features) for a
  batched input. If spatial structure across channels is needed (e.g. for a
  CNN-LSTM), reshape the last dim to (24, 8) → (batch, 26, 24, 8).

Suitable models:
  - LSTM / BiLSTM — reads the 26-step sequence, outputs one label at the end
  - GRU — lighter alternative to LSTM, often comparable accuracy
  - Transformer (encoder only) — self-attention over the 26 timesteps;
    add a CLS token or use mean pooling for the final classification
  - CNN-LSTM — 1D or 2D CNN extracts spatial features per timestep,
    LSTM models the temporal dynamics across steps
  - TCN (Temporal Convolutional Network) — causal convolutions over the
    sequence; good for real-time adaptations

Use case:
  Offline classification where capturing temporal dynamics matters. Gestures
  are not instantaneous — a hand closing has a distinct temporal profile
  different from a wrist rotation. Sequence models can exploit this. Fewer
  training samples than Format 2 (280 vs 7280 per subject) so these models
  may need more subjects to generalize. Best suited for research comparison
  against the deep learning approach (Approach A) in the project.

Inference:
  Capture the full gesture signal (1500 samples), extract all 26 windows and
  their features, stack into (26, 192), pass as a single sequence to the model
  → single predicted label. Latency: must wait for the full gesture before
  classifying (same constraint as Format 1).

─── FORMAT 4 — RAW SIGNAL (END-TO-END DEEP LEARNING) ─────────────────────────

Concept:
  No hand-crafted feature extraction. The raw preprocessed EMG signal is fed
  directly into a deep neural network that learns its own internal representations.
  This is the approach that has been the primary focus of the project so far.

Shape per sample : (1, 24, 1500)   [1 pseudo-channel, 24 electrodes, 1500 time samples]
Dataset shape    : (280, 1, 24, 1500)   [280 reps, one label per rep]
Labels           : one label per gesture rep (0–6)
Input file       : Data/X/model_ready_5/model_ready_5_sub.mat

How it works:
  The full 1500-sample signal from all 24 channels is passed as a 2D spatial-
  temporal map (24 × 1500) wrapped in a singleton dimension so it matches the
  (batch, 1, height, width) convention expected by 2D CNNs. The network sees
  the raw amplitude at every time point and every electrode simultaneously.
  No windowing, no feature computation — all representation learning happens
  inside the model through convolutions and non-linearities.

  Preprocessing applied before this stage:
    - Bandpass filter 20–500 Hz
    - Resampled to 1500 samples per rep
    - Z-score normalized per channel

Suitable models (all previously tested in this project):
  - EEGNet       — depthwise + separable convolutions over channels and time;
                   lightweight, originally designed for EEG but strong on sEMG
  - ShallowConvNet — single temporal conv + spatial pooling; fast to train
  - EMG_TCN      — Temporal Convolutional Network with residual blocks;
                   best result so far: 93.57% test accuracy (5 subjects)
  - CNN_LSTM     — CNN extracts spatial features, LSTM models temporal dynamics
  - DeepConvNet  — deeper conv stack, more parameters, needs more data

  Model files: deep_learning_approach/models.py
  Best weights: deep_learning_approach/weights/EMG_TCN_best.pt

Use case:
  Offline classification. Highest accuracy ceiling of all four formats because
  the model can learn task-specific features rather than being constrained to
  the 8 hand-crafted ones. Requires GPU for reasonable training time. Less
  interpretable than feature-based approaches — harder to understand what the
  model is responding to. Best suited for maximizing raw accuracy.

Inference:
  Capture the full gesture signal (1500 samples × 24 channels), apply the same
  bandpass + resample + z-score normalization as training, reshape to
  (1, 1, 24, 1500), forward pass → softmax over 7 classes → argmax = label.
  Latency: must wait for the full gesture to complete (same as Formats 1 and 3).

─── COMPARISON SUMMARY ───────────────────────────────────────────────────────

  Format   Sample shape       Dataset size        Label level  Real-time?  Models
  ──────   ────────────       ────────────        ───────────  ──────────  ─────────────────────
  1        (4992,)            (280, 4992)          Per rep      No          SVM, XGBoost, MLP
  2        (192,)             (7280, 192)           Per window   Yes         SVM, XGBoost, MLP, CNN
  3        (26, 192)          (280, 26, 192)        Per rep      No          LSTM, GRU, Transformer
  4        (1, 24, 1500)      (280, 1, 24, 1500)   Per rep      No          EEGNet, TCN, CNN-LSTM

─── IMPLEMENTATION PLAN ──────────────────────────────────────────────────────

  feature_extraction.py will be updated to support a `mode` parameter:

    mode="flat_window"   → current behavior, Format 2 (default)
    mode="flat_rep"      → Format 1, concatenate all windows per rep
    mode="sequence"      → Format 3, return (26, 192) per rep

  Format 4 does not go through feature_extraction.py — it uses the existing
  deep learning pipeline in deep_learning_approach/ directly.

  All three feature modes share the same underlying _extract_window() function
  and sliding window logic. Only the final assembly step differs.

  Output files will follow the naming convention:
    features_subject_03_flat_window.mat
    features_subject_03_flat_rep.mat
    features_subject_03_sequence.mat  (or .npz for array efficiency)
