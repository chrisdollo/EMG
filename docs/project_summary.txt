putEMG Prime — Project Summary
================================
Last updated: 2026-06-16

================================================================================
OVERVIEW
================================================================================

Goal: Build a generalizable, channel-efficient sEMG hand gesture recognition
system using the putEMG dataset. The project progresses through four stages:

  1. Establish within-subject baselines (compare to published benchmark)
  2. Evaluate cross-subject generalization (LOSO — leave-one-subject-out)
  3. Reduce the electrode count from 24 to 8 via feature-space clustering
  4. Retrain on the 8-channel subset and measure the accuracy trade-off

Two parallel classification pipelines run throughout every stage:
  - Deep learning  : CNN/TCN models on raw time-series (input: 1 × 24 × 1500)
  - Feature-based  : 41 single-scalar libemg features per channel → SVM / FeatureMLP

The end target is a system that generalizes to completely new subjects using
roughly one-third the electrode count, making it practical for a wearable BCI.


================================================================================
DATASET — putEMG (Kaczmarek et al., 2019)
================================================================================

  Source    : Poznan University of Technology (public, CC-licensed)
  Subjects  : 44 able-bodied participants
  Electrodes: 24 sEMG channels arranged in 3 rings of 8 around the forearm
              Elbow band = ch 1–8, middle band = ch 9–16, wrist band = ch 17–24
              Circumferential spacing: 45° per electrode
              Ch 1 of each band placed over the ulna bone, numbered clockwise
  Sampling  : 5120 Hz
  Gestures  : 7 active gestures (G1, G2, G3, G6, G7, G8, G9)
  Reps      : ~40 per gesture per subject across 2 recording sessions
  Format    : CSV per session → MATLAB preprocessing → per-subject .mat files

  Benchmark (paper): SVM + RMS features, within-subject, ~90% accuracy


================================================================================
PREPROCESSING PIPELINE
================================================================================

Step 1 — MATLAB  (data_preprocessing/matlab/put_emg_driver.m)
  CSV recordings → detect gesture blocks → extract 24 channels
  Output: per-subject combinedCell .mat  (N_reps × 7 cell array)

Step 2 — Python  (data_preprocessing/driver.ipynb + preprocessing.py)
  Runs in Google Colab; data and code stored on Google Drive.
  - Bandpass filter: 20–700 Hz (Butterworth order 4, zero-phase, applied at 5120 Hz)
  - Notch filters: 30, 50, 60, 90, 150 Hz (IIR notch Q=30, zero-phase) — mains/equipment interference
  - Resample: each rep → 1500 samples (uniform length)
  - Normalize: per-channel z-score
  Output: emg_gestures_SS_U.npz  (44 files, one per subject)

Step 3 — Feature extraction  (src/feature_extraction.py)
  Runs in Google Colab (k.ipynb) for speed, or locally via test.py.
  Sliding window: size=250 samples (~49 ms), shift=50 samples → 26 windows/rep
  41 single-scalar libemg features × 24 channels = 984-dim per window
  Layout: CHANNEL-MAJOR — each channel is a contiguous 41-feature block, so
          channel c occupies columns [c*41 : (c+1)*41]. This makes the 24→8
          channel reduction a clean column slice (no re-extraction needed).
  Output format: (N_reps, 26 × 984) = (N_reps, 25584) flat_rep per subject
  Output files : data/features/{train,eval}/features_SS_flat_rep.npz

  Only the 41 features that emit exactly ONE scalar per channel are kept, so the
  feature dimension scales linearly with channel count. Of libemg's 50 groups, 9
  are EXCLUDED:
    multi-scalar within-channel : AR, CC, DFTR, WENG, WV, WWL, WENT
    cross-channel (phasor)      : RMSPHASOR, WLPHASOR

  The 41 retained features (one scalar/channel each):
    MAV, ZC, SSC, WL, LS, MFL, MSR, WAMP, RMS, IAV,
    DASDV, VAR, M0, M2, M4, SPARSI, IRF, WLF, LD, MAVFD,
    MAVSLP, MDF, MNF, MNP, MPK, SKEW, KURT, PAP, MZP, TM,
    SM, SAMPEN, FUZZYEN, ISD, COR, MDIFF, MLK, ACT, MOB, COMP, MEAN

  (Previous format used all 50 groups = 133 scalars/channel = 3192-dim/window;
   feature-based results below predate the switch and will be re-run.)


================================================================================
MODELS
================================================================================

Deep Learning  (src/deep_learning_models.py)
  EEGNet        — compact depthwise-separable CNN (adapted from EEG literature)
  ShallowConvNet — shallow CNN from Schirrmeister et al.
  EMG_TCN       — temporal convolutional network, best-performing overall

Feature-Based  (src/runners.py + src/feature_based_models.py)
  Within-subject (WITHIN_FEATURE_MODELS):
    SVM        — RBF kernel, C=50, window-level training, majority vote
    FeatureMLP — 3-layer MLP on per-window 984-dim features, majority vote

  Cross-subject (CROSS_FEATURE_MODELS):
    SGD_SVM    — SGDClassifier(loss='hinge'), full ~303k window-level training, majority vote
                 (SGD used instead of LinearSVC: O(n) per pass, tractable on full pool;
                  equivalent to linear SVM but stochastic)
    FeatureMLP — same as within-subject

  The protocol (window-level training + majority vote) is identical at both
  scales; only the optimizer differs due to scale constraints.

All DL models use:
  - Adam optimizer, LR 1e-3
  - ReduceLROnPlateau (factor 0.5, patience 5)
  - Early stopping (patience 5), max 20 epochs
  - Batch size 16


================================================================================
EVALUATION PROTOCOLS
================================================================================

Within-Subject (Phase 1)
  - 3-fold stratified CV per subject, seed 42
  - Train/test split within one subject's data
  - Directly comparable to the putEMG paper benchmark (~90%)

Cross-Subject — LOSO (Phase 2)
  - 44 folds: each subject serves as the test set once
  - Train = remaining 43 subjects (10% held out as validation for DL)
  - Tests generalization to completely unseen individuals
  - Gold standard for real-world BCI deployability

================================================================================
CHANNEL SELECTION — PHASE 3 METHODOLOGY
================================================================================

Goal: identify 8 physical electrode positions (from 24) that capture the most
information with minimum inter-channel redundancy — suitable for a fixed-layout
wearable sleeve.

Method: window-level Pearson correlation → agglomerative clustering → MI selection
Entry : scripts/run_clustering.py

  Step 1 — Consensus redundancy matrix
    For each of the 41 per-channel features, compute the 24×24 Pearson correlation
    matrix across all ~311k windows (all 44 subjects × 26 windows/rep).  Average
    over all 41 features → one consensus (24, 24) redundancy matrix.
    Mean off-diagonal correlation: 0.84 — channels are highly redundant overall.

    Rationale: correlating at the window level (not via per-channel mean vectors)
    preserves gesture-conditional covariation. Two channels with identical means but
    different activation patterns across gestures would be incorrectly grouped by
    the mean approach; window-level correlation catches this.

  Step 2 — Agglomerative clustering (k=8)
    Distance = 1 − r; average linkage; silhouette sweep k=4–12.
    Best silhouette at k=7 (score 0.283); k=8 used to match hardware target.
    Silhouette at k=8 = 0.249 — reasonable fit, one cluster is a mild forced split.

  Step 3 — MI-ranked representative selection
    Within each cluster, compute mean MI(channel features, gesture labels) across
    all 41 features. Select the highest-MI channel as the cluster representative.
    This combines redundancy control (from clustering) with informativeness
    maximisation (from MI) — neither alone is sufficient.

  Selected channels (0-indexed): [0, 1, 5, 7, 14, 16, 19, 22]
  Labels: E0°, E45°, E225°, E315°, M270°, W0°, W135°, W270°
  Ring coverage: Elbow 4, Middle 1, Wrist 3 (all three rings represented)

  Notable clusters:
    Cluster 3 (6 channels): E45°, E90°, E135°, E180°, M90°, M135° — all anterior
    forearm electrodes; collapsed to representative E45° (highest MI = 0.092).
    The middle ring (ch 8–15) is almost entirely dropped; only M270° survives.
    This is anatomically consistent: the middle ring records a weighted mix of
    what the elbow and wrist rings already capture.

  Methodological references: see REFERENCES section.

    Journal of Healthcare Engineering. https://doi.org/10.1155/2021/9929684

    to use clustering for redundancy control rather than pure MI top-k ranking.

  Scheme, E., et al. (2020).
    Automated Channel Selection in High-Density sEMG for Improved Force Estimation.
    Sensors, 20(19), 5679. https://doi.org/10.3390/s20195679
    PMC: https://pmc.ncbi.nlm.nih.gov/articles/PMC7576492/
    Relevance: introduced the Power-Correlation Ratio (PCR), which explicitly
    averages Pearson correlation coefficients of each channel against all others
    across recording windows to estimate inter-channel redundancy. Directly
    supported our window-level (not mean-vector-level) correlation approach.
