--------------------------------------------------------------------------------
1. OVERVIEW
--------------------------------------------------------------------------------

This project builds an EMG-based gesture recognition system using the putEMG
dataset (44 subjects, 24 sEMG channels, 5120 Hz, 7 gesture classes). Two
parallel pipelines have been developed:

  A) Deep Learning — raw signal CNN/TCN models
  B) Feature Approach — hand-crafted features (8 features × 24 channels) fed
     into classical ML or sequence models

The deep learning pipeline is complete and has achieved a strong 93.57%
accuracy using EMG_TCN. The feature approach is partially built — extraction
code is fully implemented, formats are specified, and data for 26 subjects in
sequence format has been generated, but model training across all three feature
formats has not yet been completed.

Overall, this is a well-structured and thoughtfully designed project. The
preprocessing is rigorous, the feature engineering is appropriate for EMG, and
the deep learning results are competitive with the putEMG paper baseline
(SVM+RMS ~90%). The codebase is clean, modular, and easy to extend.

2. WHAT HAS BEEN ACCOMPLISHED
--------------------------------------------------------------------------------

PREPROCESSING PIPELINE
  - Bandpass filter (20-500 Hz, zero-phase Butterworth) before resampling is
    correct signal processing practice — avoids aliasing and removes noise.
  - Resample to fixed length (1500 samples) ensures uniform input across all
    gesture repetitions regardless of original duration.
  - Per-channel z-score normalization removes inter-subject amplitude variance
    and electrode placement variability.
  - Pipeline is modular: `preprocess_gesture()`, `process_subject_file()`,
    `batch_process_subjects()` — clean and reusable.
  - Status: COMPLETE and well-implemented.

FEATURE EXTRACTION
  - Implements 8 standard EMG features per channel: MAV, RMS, WL, ZC, SSC,
    VAR, MNF, MDF. This covers both time-domain and frequency-domain
    information, which is standard and effective for EMG classification.
  - Sliding window design (250 samples / 49 ms window, 50 sample / 9.8 ms
    shift) yields 26 windows per gesture repetition.
  - Three output modes implemented: flat_rep, flat_window, sequence.
  - Status: COMPLETE. Code is correct and flexible.

DEEP LEARNING APPROACH
  - Five architectures implemented: EEGNet, ShallowConvNet, DeepConvNet,
    CNN_LSTM, EMG_TCN.
  - EMG_TCN is the clear winner (93.57%) — dilated temporal convolutions with
    residual connections are well-suited to EMG time series.
  - Training infrastructure (train/val/test split, early stopping, checkpoint
    saving) is in place.
  - Best weights saved to disk.
  - Status: COMPLETE. This is the strongest result in the project so far.

FEATURE APPROACH — DATA & FORMATS
  - Format 1 (flat per rep): Spec written, extraction supported, no model yet.
  - Format 2 (flat per window): Spec written, model notebook exists, no
    reported results yet.
  - Format 3 (sequence per rep): Spec written, data handler written, sequence
    features extracted for 26 subjects, model notebook exists, no reported
    results yet.
  - Status: PARTIAL. Foundation is solid; training and evaluation missing.

CHANNEL CLUSTERING
  - K-Means clustering pipeline on feature data implemented (PCA → K-Means,
    k=8, evaluated with silhouette, ARI, NMI, purity, elbow plot).
  - Objective: reduce 24 channels to 8 representative channels to cut feature
    dimensionality from 192 → 64.
  - Status: PARTIAL. Code runs but results have not been analyzed or acted upon.

3. STRENGTHS
--------------------------------------------------------------------------------

1. COMPETITIVE DEEP LEARNING RESULT
   93.57% with EMG_TCN on 5 subjects beats the putEMG paper baseline (SVM+RMS
   ~90%), and the architecture choices (TCN with causal padding, dilated
   convolutions, spatial mixing) are well-reasoned for EMG.

2. DUAL PIPELINE DESIGN
   Running a feature-based pipeline alongside deep learning is scientifically
   valuable. It allows direct comparison between learned representations and
   hand-crafted features, and the feature approach is far more interpretable.

3. REAL-TIME CAPABILITY IN FORMAT 2
   The sliding window approach in Format 2 (flat per window) enables real-time
   inference — each 49 ms window is classified independently, latency is
   determined by window size, not rep length. This is important for BCI
   applications and is often overlooked in offline-only projects.

4. CLEAN, MODULAR CODE
   preprocessing.py, feature_extraction.py, models.py, emg_datahandler.py,
   and handler.py are all reasonably decomposed. Adding new features, new
   models, or new preprocessing steps is straightforward.

5. PREPROCESSING IS CORRECT
   Applying the bandpass filter before resampling is the correct order
   (avoids aliasing artifacts). Per-channel z-score normalization is also
   correct and important for inter-subject generalization.

6. LARGE FEATURE DATASET PARTIALLY READY
   26 subjects of sequence-format features already extracted. This is a
   significant asset that is not yet fully exploited.

4. WEAKNESSES & GAPS
--------------------------------------------------------------------------------

1. NO BASELINE ACCURACY FOR FEATURE FORMATS
   The feature approach pipeline (Formats 1, 2, 3) has no reported accuracy
   results. It is impossible to compare the three formats or evaluate whether
   the feature approach is competitive without these numbers.

2. ONLY 5 SUBJECTS FOR DEEP LEARNING
   The deep learning model was trained and evaluated on only 5 of the 44
   available subjects. This severely limits confidence in the result — the
   model may be overfit to the specific subjects used, and there is no evidence
   of how it generalizes to unseen subjects.

3. NO CROSS-SUBJECT GENERALIZATION TEST
   All evaluations appear to be within-subject or pooled across 5 subjects with
   a random split. There is no leave-one-subject-out (LOSO) or cross-subject
   experiment. This is the most critical missing evaluation for a BCI system.

4. CLUSTERING RESULTS NOT ACTED UPON
   The channel clustering notebook runs but the results have not been analyzed
   or used to select representative channels. The planned 24 → 8 channel
   reduction has not been completed, so the feature dimensionality comparison
   (192-dim vs 64-dim) has not been done.

5. FORMAT 2 AND FORMAT 3 MODEL NOTEBOOKS STATUS UNCLEAR
   The notebooks exist in /formats/format2_flat_window/model/ and
   /formats/format3_sequence/model/ but it is unclear if they contain trained
   models with results or just stubs.

6. CNN_LSTM AND DEEPCONVNET ARE WEAK
   CNN_LSTM achieved only 51.43% and DeepConvNet 59.64% — both are barely
   above chance (14.3% random baseline). These architectures as configured are
   not working well for this problem.

7. SMALL TRAINING SET FOR DEEP LEARNING
   1400 total samples (5 subjects × 280 reps) is quite small for deep learning.
   This may explain why CNN_LSTM and DeepConvNet underperform — they have more
   parameters and need more data to train effectively.

8. NO LEARNING RATE SCHEDULING
   Training uses a fixed Adam learning rate. Learning rate scheduling (e.g.,
   ReduceLROnPlateau or CosineAnnealingLR) would likely improve convergence
   and final accuracy.

9. NO MAJORITY VOTING / ENSEMBLE FOR FORMAT 2
   Format 2 classifies each window independently, but for offline evaluation a
   majority vote over the 26 windows of a rep would improve accuracy and
   stability. This has not been implemented yet.

5. IMPROVEMENT IDEAS
--------------------------------------------------------------------------------

--- HIGH IMPACT / LOW EFFORT ---

A) TRAIN AND EVALUATE ALL THREE FEATURE FORMATS
   Generate flat-window and flat-rep feature files for the 26 subjects
   already preprocessed, then train SVM / XGBoost / MLP baselines and report
   accuracy. This is the single highest-value missing piece.

   Suggested baseline stack per format:
     Format 1: SVM (RBF), LinearSVC, XGBoost
     Format 2: LinearSVC, XGBoost (one window at a time), + majority vote
     Format 3: LSTM, GRU, BiLSTM (using handler.py already written)

B) ADD MAJORITY VOTING FOR FORMAT 2
   After per-window predictions, aggregate over the 26 windows of each rep:
     final_prediction = mode(window_predictions_over_rep)
   This typically boosts Format 2 accuracy 3-8% over raw per-window accuracy.

C) SCALE DEEP LEARNING TO MORE SUBJECTS
   The preprocessing pipeline and models are already in place. Expanding from
   5 to 20+ subjects requires only running batch_process_subjects() on more
   data and retraining. More subjects → better generalization and more reliable
   accuracy estimates.

D) LEARNING RATE SCHEDULING
   Add CosineAnnealingLR or ReduceLROnPlateau to the training loop in
   emg_datahandler.py. This is a few lines of code and typically yields 1-3%
   accuracy improvement.
   Example:
     scheduler = CosineAnnealingLR(optimizer, T_max=num_epochs)
     # or
     scheduler = ReduceLROnPlateau(optimizer, patience=5, factor=0.5)

E) FIX BEST_STATE RESTORATION IN TRAINING
   If the training loop in emg_datahandler.py does not correctly restore the
   best validation checkpoint before evaluation (a common subtle bug), the
   reported accuracy may be for a suboptimal epoch. Verify that model weights
   are loaded from best_state_dict before computing test accuracy.

--- MEDIUM IMPACT / MEDIUM EFFORT ---

F) LEAVE-ONE-SUBJECT-OUT (LOSO) EVALUATION
   Split the data so that training uses N-1 subjects and testing uses the held-
   out subject. Repeat for all subjects. This gives the most honest measure of
   how the model performs on a new user without re-calibration.

   Expected result: accuracy will drop (potentially significantly). This is
   the most important evaluation to run before claiming the system is useful.

G) ANALYZE AND ACT ON CLUSTERING RESULTS
   Run the clustering notebook, record silhouette score and cluster purity, and
   use the best-cluster representative to select 8 channels. Then retrain all
   three feature format models on the 64-dim reduced features and compare
   accuracy versus the 192-dim baseline. This answers the question: do we
   need all 24 channels?

H) PER-REP Z-SCORE VS PER-CHANNEL GLOBAL Z-SCORE
   Currently z-score normalization is applied globally per channel (using mean
   and std across all time samples in a rep). Consider computing normalization
   statistics per-subject during training and applying the same transform at
   test time. This is closer to what a real deployment system would do.

I) DATA AUGMENTATION FOR DEEP LEARNING
   With only 1400 samples, augmentation can meaningfully improve generalization:
     - Gaussian noise addition (simulate electrode noise)
     - Amplitude scaling (simulate different muscle contractions)
     - Time warping or time shift (within the 1500-sample window)
     - Channel dropout (simulate missing/noisy electrodes)

J) INVESTIGATE CNN_LSTM AND DEEPCONVNET FAILURES
   Before discarding these architectures, diagnose why they perform so poorly:
     - Check for gradient vanishing/exploding (log gradient norms during training)
     - Try much smaller LR for LSTM (1e-4 or lower)
     - Check that input shapes are correct
     - Try with more data (more subjects)
   CNN_LSTM at 51.43% on 7 classes is barely above chance — something is wrong.

--- LOWER IMPACT / HIGHER EFFORT ---

K) SUBJECT-ADAPTIVE FINE-TUNING
   Train on all N-1 subjects, then fine-tune the last 1-2 layers on a small
   calibration set from the new subject (e.g., 5-10 reps per gesture). This
   is the most practical deployment scenario for a BCI.

L) FEATURE IMPORTANCE ANALYSIS
   For the trained feature-approach models, use SHAP or feature importance
   scores (XGBoost built-in) to identify which of the 192 features contribute
   most to classification. This gives scientific insight into which features
   and channels carry the most discriminative information per gesture.

M) GESTURE CONFUSION ANALYSIS
   Plot per-class confusion matrices for each model. EMG gestures often have
   characteristic confusion patterns (e.g., G6 and G7 may be harder to
   distinguish). Understanding where models fail guides future improvements
   more precisely than top-line accuracy alone.

N) ONLINE/REAL-TIME INFERENCE PROTOTYPE
   For Format 2, implement a simple simulation that feeds windows one at a time
   (every 10 ms) and outputs predictions. Measure latency and accuracy versus
   ground truth. This bridges the gap from offline research to real application.

O) COMPARE AGAINST MORE BASELINES
   The putEMG paper reports SVM+RMS ~90%. More complete comparisons:
     - SVM + all 8 features (vs. just RMS)
     - XGBoost + 192 features
     - Random Forest
     - MLP (1-2 hidden layers)
   These are fast to train and establish a proper baseline for the feature
   approach before investing in deep learning comparisons.

P) INCREASE GESTURE CLASSES OR SUBJECTS TO MATCH PAPER
   The putEMG dataset has 8 active gestures (G1-G3, G6-G9, plus rest). This
   project uses 7. Consider including the rest class (G0) to make the problem
   harder and more realistic. Also consider scaling to all 44 subjects to
   match the full-dataset results in the original paper.
